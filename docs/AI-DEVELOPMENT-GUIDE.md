# AI 开发约束协议

> 本文件定义了 AI 参与 ZPW 项目开发的强制约束和流程规范
> 版本：v1.0 | 创建日期：2026-05-02

---

## 一、强制约束

### 1.1 文档优先原则

- **所有开发必须基于 `/docs` 目录下的技术文档**
- 禁止跳过任何文档内容进行"猜测"开发
- 禁止在未读取相关文档的情况下直接编写代码
- 遇到文档不明确或缺失的地方，**必须先提问确认**，禁止自行假设

### 1.2 开发前准备

每次开发任务前，AI 必须：

1. 读取相关技术文档（根据任务类型选择）：
   - 后端 API 开发 → 读取 `06-API接口规范-上.md` 或 `06-API接口规范-下.md`
   - 数据库开发 → 读取 `03-数据库设计.md`
   - 前端页面开发 → 读取 `04-页面设计与交互.md`
   - 业务流程开发 → 读取 `05-功能流程图.md`
   - 安全/部署相关 → 读取 `08-安全与性能.md`、`09-部署说明.md`

2. 查阅项目进度文档 `项目进度跟踪文档.md`，确认：
   - 当前开发单元的状态
   - 依赖的前置开发单元是否已完成
   - 相关的数据表、路由、Model 是否已创建

### 1.3 开发后验证

完成代码编写后，必须对照文档验证：

- [ ] API 参数是否与文档一致
- [ ] 响应结构是否符合文档规范
- [ ] 业务逻辑是否符合流程图描述
- [ ] 数据库字段是否与表设计匹配

## 二、开发流程

### 2.1 标准开发流程

```
任务接收 → 读取相关文档 → 查阅进度文档 → 编写代码 → 对照验证 → 更新进度 → 记录开发记忆
```

### 2.2 任务开始标准

AI 接受开发任务时，必须满足以下条件之一：
- 用户已提供完整的开发需求
- 用户已指定需要参考的文档章节
- AI 已完成文档阅读并理解需求

### 2.3 遇到问题时的处理

| 问题类型 | 处理方式 |
|---------|---------|
| 文档未明确规定 | 提问用户确认，不要自行假设 |
| 文档存在矛盾 | 优先遵循最新版本的文档，或提问确认 |
| 缺少必要的依赖 | 暂停当前任务，告知用户前置依赖未完成 |
| 发现文档错误 | 记录到开发记忆，并向用户报告 |

## 三、进度管理

### 3.1 进度文档位置

所有开发进度记录在：`/docs/项目进度跟踪文档.md`

### 3.2 状态标记规范

| 符号 | 含义 | 使用场景 |
|-----|-----|---------|
| ⬜ | 未开始 | 新任务开始前 |
| 🔵 | 进行中 | 正在开发中 |
| ✅ | 已完成 | 开发完成并通过验证 |
| ❌ | 阻塞/问题 | 遇到无法解决的问题 |
| ⏭ | 暂缓/跳过 | 因依赖未完成而暂停 |

### 3.3 更新要求

- 每个开发单元完成后，必须更新状态为 ✅
- 遇到问题时，更新状态为 ❌ 并说明原因
- 完成后在备注栏注明：已完成日期、遇到的问题及解决方案

---

## 四、开发记忆

### 4.1 记忆文档位置

开发记忆记录在：`/docs/AI-开发记忆.md`

### 4.2 记录内容

每次开发完成后，必须记录：

- **开发日期**：2026-05-02
- **开发单元**：具体的功能模块
- **参考文档**：使用的技术文档章节
- **完成内容**：简要描述完成的工作
- **问题与解决**：遇到的问题及解决方案
- **代码约定**：本次开发中建立的代码规范

### 4.3 记忆复用规则

后续开发时，AI 必须先查阅开发记忆：
- 检查是否有类似功能的开发经验
- 遵循已有的代码约定
- 避免重复踩坑

---

## 五、禁止事项

1. **禁止跳过文档阅读直接开发**
2. **禁止在未验证的情况下"假设"文档内容**
3. **禁止忽略进度文档中的依赖关系**
4. **禁止在未更新进度的情况下结束开发任务**
5. **禁止添加文档中未定义的功能或字段**

---

## 六、例外情况

如果遇到以下情况，AI 可以适当灵活处理：

1. 用户明确要求使用新技术/新方案
2. 文档中明确标注"可灵活实现"的模块
3. 修复明显的拼写错误或代码 bug

但应在开发记忆中进行记录，并在完成后告知用户。

---

## 七、版本管理

- 本协议如有修改，发布新版本并注明变更内容
- AI 开发时遵循最新版本的协议
- 历史版本保留供参考
